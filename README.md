# TT Time Trade

TT Time Trade is a skill-sharing platform where learners and mentors can connect, share courses, and exchange help. The app includes learner and mentor experiences, course listings, urgent help requests, a credit wallet, and an AI chat assistant.

## Technology

- Frontend: React 18, Vite, and Framer Motion
- Authentication and realtime data: Firebase Authentication and Realtime Database
- Relational data: Supabase
- Backend: Node.js, Express, and Supabase
- Optional backend integrations: Groq, Firebase Admin, and SMTP email

## Requirements

- Node.js 18 or newer and npm
- Firebase and Supabase projects configured for this app
- Optional: Groq API access, SMTP credentials, and Firebase Admin credentials for the related backend features

## Local setup

1. Clone this repository and open its directory:

   ```sh
   git clone https://github.com/india-coderr/tutor_token.git
   cd tutor_token
   ```

2. Install dependencies for the frontend and backend:

   ```sh
   npm install
   cd backend
   npm install
   cd ..
   ```

3. Configure the frontend:

   ```sh
   cp .env.example .env
   ```

   `VITE_BACKEND_URL` defaults to `http://localhost:4000`. The Firebase web configuration and Supabase URL/anon key are currently defined in `src/App.jsx` and `src/lib/api.jsx`; replace them with your own client configuration before using the app with your services. These values are included in browser code and must not be treated as private secrets.

4. Configure the backend:

   ```sh
   cp backend/.env.example backend/.env
   ```

   Fill in the required service credentials described below. To create an admin password hash, run this from `backend`:

   ```sh
   npm run hash-password -- "use-a-strong-password"
   ```

   Put the generated hash in `ADMIN_PASSWORD_HASH`. Do not commit either `.env` file or share real credentials.

5. Configure the external services:

   - In Firebase, enable Google sign-in and set up Realtime Database. Add your deployed app origins to the relevant Firebase authorized-domain settings.
   - In Supabase, apply `backend/migrations.sql` to the database. This is an incremental migration, not a complete schema for a new project: it assumes the app's base `courses` and `requests` tables already exist.
   - Configure Firebase, Supabase, and any optional Groq or SMTP services with credentials for your own projects.

6. Start the backend and frontend in separate terminals:

   ```sh
   cd backend
   npm run dev
   ```

   ```sh
   npm run dev
   ```

   The Vite frontend runs at `http://localhost:5190`; the backend defaults to `http://localhost:4000`. Check backend availability at `http://localhost:4000/api/health`.

## Environment variables

The complete backend template is in [`backend/.env.example`](backend/.env.example).

| Variable | Required | Purpose |
| --- | --- | --- |
| `PORT` | No | Backend port; defaults to `4000`. |
| `FRONTEND_ORIGIN` | Yes for browser requests | Comma-separated frontend origins allowed by CORS. Defaults to `http://localhost:5190`. |
| `JWT_SECRET` | Yes | Secret used to sign and verify admin login tokens. Use a long, random value. |
| `ADMIN_EMAIL` | Yes for admin login | Admin account email. |
| `ADMIN_PASSWORD_HASH` | Yes for admin login | Bcrypt hash generated by the backend script. |
| `SUPABASE_URL` | Yes | Supabase project URL used by the backend. |
| `SUPABASE_SERVICE_KEY` | Yes | Supabase service-role key. Keep this server-side and private. |
| `FIREBASE_DATABASE_URL` | Feature-dependent | Firebase Realtime Database URL for backend Firebase Admin features. |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | Feature-dependent | Firebase Admin service-account JSON as a single-line JSON string; alternatively use application-default credentials. |
| `GROQ_API_KEY` | Optional | Enables the backend's Groq-powered AI endpoints. |
| `GROQ_MODEL` | Optional | Groq model name; defaults to `openai/gpt-oss-120b`. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` | Optional | SMTP settings used for approval email. |

Frontend variables use Vite's `VITE_` prefix and are embedded in the browser build; never put private credentials in them. The frontend backend URL can be changed using `VITE_BACKEND_URL`.

## Production build

Build the static frontend:

```sh
npm run build
```

The generated files are in `dist/`. Deploy the backend in `backend/` as a separate Node.js service, configure its environment variables, set `FRONTEND_ORIGIN` to the deployed frontend origin, and set the frontend's `VITE_BACKEND_URL` to the deployed backend URL before building.

## Secrets and configuration

Never commit `.env` files, Supabase service-role keys, Firebase service-account credentials, JWT signing secrets, Groq keys, or SMTP passwords. Firebase web configuration and the Supabase anon key are client-side settings and are visible to every browser user; use provider-side restrictions and database access policies. Keep privileged credentials in the backend environment only.
